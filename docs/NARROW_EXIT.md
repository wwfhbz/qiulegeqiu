# V0.5 底部窄出口

## 基线与审核关系

main 当前为 V0.4，中央按钮功能位于未合并的 PR #2。本改动从 feature/central-start-v05 的 d8950ea 起步，提交到 feature/narrow-exit-v05，PR 以该分支为基线，便于分别审核。没有合并 main 或发布腾讯云。

代码实际为已确认的三关，未找到十关/障碍配置；本次原样保留关卡和计分规则，没有新增十关或声称验证不存在的系统。三命、积分、连击、道具、音效、100 球与中央开始交互均保留。

## 真实几何与尺寸

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 圆心 | (400,492) | 不变 |
| 半径 | 360 | 不变 |
| exitHalfWidth | 106 | 53 |
| 圆弧端点之间的水平弦宽 | 212 | 106（精确50%） |
| 挡板中心 y | 938 | 1018 |
| 圆底到挡板上边缘 | 80 | 160（本次明确要求） |
| Canvas | 800×1040 | 800×1120 |
| 挡板下方可用高度 | 102 | 102 |

新端点为 x=347/453、y=492+sqrt(360²−53²)，约 y=848.077。围挡两侧沿同一个圆弧延伸，竞技场本体不移动或缩放。

名义开口以圆弧路径端点计算，为 106。新描边宽 1.4，使用圆端盖，因此端点水平线处可见净宽约为 **104.6**。球半径为 4.5，球中心在同一水平线的无接触通道宽度约 **95.6**；有限尺寸球的通道与端点弦宽是不同口径。本次严格执行需求中的半宽 106→53。旧物理用 x 方向条带判断，球中心宽度约 203；旧绘制没有圆端盖，不将它当作与新描边相同的净宽来宣称精确减半。

## 绘制与碰撞一致性

ArenaGeometry.ts 从同一 GameConfig 计算圆弧起止角、左右端点、描边宽和开口扇区。

- Renderer 直接使用这些角度，绘制 1.4 厚度的圆端盖围挡。
- Physics 对封闭弧使用径向最近点；对开口扇区内的球使用最近圆端点。接触距离统一为球半径加半描边宽。
- 端点采用真实圆角法线反射及位置修正，不使用整条竖直通道代替圆弧，避免视觉已经封闭但球仍穿过。
- 保留圆内/圆外标记，只有整个球穿过壁面后切换，避免接触带内反复切换。圆外碰弧使用朝外法线，不吸入圆内。
- 仍使用 1/120 秒固定步长和最多 2 逻辑像素子步进。球出圆后继续模拟，可被圆外挡板接住并返回；只有完全离开加高后的 Canvas 才回收。
- 挡板造型、宽度、厚度、颜色、水平移动、加宽机制和原有角度控制均保留。

## 实际验证

类型检查、75 项单元测试与生产构建通过。保留 65 项既有测试，按新高度调整位置/时间夹具；新增 10 项出口测试，覆盖：50%弦宽、绘制与物理端点一致、两侧新增弧反弹、高速中心往返、圆端盖、圆外反射与端点离开、百球往返、72 个径向入射角中所有闭合弧方向无穿墙、圆心和160间距。

生产包浏览器验证包括：

- 像素采样确认新增弧两侧与端点存在、出口中心无围挡；真实帧循环确认新增围挡反弹及出圆—接球—回圆。
- 中央按钮点击后整层隐藏；底部只保留暂停/继续和重新开始；真实触摸、窄屏和零尺寸恢复回归通过。
- 三命、计分、通关和原道具、音效、多球浏览器回归通过。三关结算使用真实销毁事件快速构造，并非手工打完全部方块。
- 持续百球桌面 Chromium 两阶段各5秒测量约60 FPS，仅代表当前环境，手机真机性能未验收。
