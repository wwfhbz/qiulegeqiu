# 弹球水平/局部循环修复

基线：main `6217704`。

## 根因与可复现证据

原反射仅执行法线反射：圆外左右墙的法线为水平向量，`vy=0` 反射后仍为0。原引擎没有逐球进展、侧墙链或轨迹循环检测，因此球可以永远停留在圆外同一高度，既碰不到挡板也越不过死亡线。

受控真实Physics夹具：球 `(400,930)`、速度 `(440,0)`、圆外，挡板固定100，排除砖块干扰。基线源码独立worktree运行16秒，球每次左右反弹后仍然y=930且存活；修复分支的旧轨迹模式逐秒位置/速度与基线完全一致。新版第1秒y≈943.75、vy≈88，第2秒y≈1031.75，之后正常漏过挡板并完整越过死亡线；没有由防卡死模块删除球。[逐秒原始数据](ball-motion/reproduce.json)。

`tests/ball-motion.test.ts` 同样保留旧版本0可复现与新版本1脱离的回归，不删除失败场景。

## 最小共享实现

新增纯数值模块 `src/BallMotion.ts`，Web和微信继续共用同一个Game/Physics，不引入平台分支或另一套物理。

- `verticalRatio=.20`：发生方向碰撞后重建速度分量，保持原速率。优先保留原vy符号，精确水平（含-0）向下；如果提高vy会让速度重新指向实体内部，优先保证离开碰撞面。正常大于阈值的反弹保持原样。
- `wallHits=6`：每球独立记录交替左右侧墙接触。只统计真实反射，不把重复贴墙分离计为新反弹。顶部/其他墙面、机关接触打断侧墙链；砖块、挡板接触也打断且记录有效进展。
- `timeout=8`：使用仿真时间，且必须有明显水平往返或局部闭环证据。仅8秒没打砖不纠偏。连续直线与大范围正常运动测试不触发。
- 每0.5仿真秒采样，保存8个位置/方向变化计数；水平证据为窗口高度≤32、X方向至少2次翻转；局部证据为宽高均≤200、至少4次方向翻转且回到旧样本64像素范围。参数集中在MOTION中。
- 确认循环后保持速率，将vy改为正向0.65比例，vx使用原有左右方向（未知时使用固定侧墙规则）；不移动位置、不删球、不扣命。
- 强纠偏至少2秒冷却，并重建采样窗口；有效砖块/挡板进展清除循环标记。机关能打断侧墙链，但自身往返不能一直伪装成有游戏进展；穿透打砖只记进展，不凭空改变方向。
- 每球状态含仿真时间、最后进展、侧墙数、最后侧、方向符号、循环标记、纠偏原因/次数、冷却及固定40项Float64Array。每球独立，池化重生与派生新球重置，绝不继承旧回合卡死状态。
- 没有Math.random、Date.now或performance.now参与纠偏；Physics固定步进和确定性几何决定结果。暂停/后台不执行仿真，也不累计冷却或卡死时长。

Physics/Obstacles的碰撞回调复用实例函数，不在每帧创建碰撞对象。普通砖块、道具、速度上限、挡板几何、生命与计分公式均未修改。

## 轨迹版本与旧记录兼容

**不升级计分rulesVersion，也不改变榜单赛季。** 当前闯关仍为 `1.8.0-arcade-5l-12lv-powerpts-v6`，无尽仍为 `endless-1.3.0-3l-sink-v4`。物理轨迹的变化另行明确记录，不能假装新旧物理完全相同：

```json
{"type":"launch","level":1,"tick":0,"trajectoryVersion":1}
```

仅首次launch包含此字段；后续发射重复声明、未知版本或错误类型拒绝。旧日志不含字段，明确解释为轨迹0；`trajectoryVersionFor(events)` 提供相同选择规则。若需用共享Physics重现旧轨迹，在reset/spawn前设置 `physics.trajectoryVersion=trajectoryVersionFor(events)`；0完整绕过新纠偏，1启用新规则。

服务器 `/health` 和 `/challenges` 均声明 `deterministic-trajectory-v1` 能力。新客户端在两个阶段都检查，防止混合新旧API实例时上传不兼容日志；部署检查同样要求该能力。协议2保留，通过显式可选扩展与能力握手兼容，不静默删字段迁就旧服务端。

| 客户端 | 后端 | 行为 |
|---|---|---|
| 旧 | 旧 | 原逻辑 |
| 旧 | 新 | 支持；缺标记的旧日志仍合法，旧客户端忽略附加能力 |
| 新 | 旧 | 明确提示后端需升级，停止联网日志提交，可继续单机；不伪装为有效成绩 |
| 新 | 新 | 使用轨迹1，严格检查首次标记，按原计分与反作弊规则回放 |

**现有服务端不是完整物理重放。** 它重建事件顺序、掉落、无尽砖墙、生命和积分，日志没有完整挡板输入，不能据此重新计算全部物理位置。本次没有将客户端纠偏事件当作权威证明，也没有声称增加了服务端权威物理。测试分别验证Web/微信同源轨迹完全相同，以及其物理生成的事件/成绩通过现有服务端回放；新旧轨迹版本为后续真实物理重放保留清晰语义。

数据库无需迁移。标记保存在既有挑战事件JSON中；历史事件和成绩不重写、不重算、不删除。API测试同一旧玩家提交新旧版本记录均能验证，幂等与伪造分数拒绝保留；原短局隔离、击碎预算、道具拾取和事件次序检查未放宽。
